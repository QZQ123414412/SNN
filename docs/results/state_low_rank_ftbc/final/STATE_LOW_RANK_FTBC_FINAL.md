# 状态条件低秩 FTBC 最终实现与结果

## 1. 最终方法

在原有 `SNM + R0 + FTBC` 上，将每层完整的逐时间步偏置

```text
b_c(t), 参数量为 T*C
```

改为共享 SNM/R0 状态的低秩形式：

```text
g(t) = transmitted(t-1) > 0
b_c(t,g) = base_c + slope_c * t/(T-1) + state_c * g(t)
```

- `base`：通道基础误差；
- `slope`：误差随时间的线性变化；
- `state`：当前仍存在可撤销净正输出时的额外校正；
- 参数量从 `T*C` 降为 `3*C`；
- `T=1/2` 时自动退化为完整 FTBC，避免低秩形式反而增加存储。

校准使用在线累积的 `XTX[通道,3,3]` 和 `XTy[通道,3]`，每层只需求解通道独立的 `3x3` 岭回归。最终配置对正偏差使用更高权重：

```text
over_weight = 2.0
under_weight = 1.0
```

其目标是优先抑制过发放，减少“先产生正脉冲、再由 SNM 用负脉冲撤销”的双重 SOPs。

## 3. 延迟结论

统计代码原来在每层、每时间步调用 `.item()`，会频繁强制 GPU 同步。现已改为 GPU 端累计，并用关闭统计的独立前向测量纯推理时间。

| T | Full FTBC | State-LR FTBC | 说明 |
|---:|---:|---:|---|
| 4 | 11.7s | 11.9s | 额外延迟很小 |
| 8 | 13.4s | 13.9s | 额外延迟约 3.7% |
| 16 | 18.8s | 20.1s | 额外延迟约 6.9% |
| 32 | 29.7s | 49.9s | eager PyTorch 下逐元素状态门控开销明显 |

`T=32` 延迟对连续运行、GPU 状态和临时张量分配较敏感，正式论文应独立预热后重复至少五次，报告中位数和标准差。当前不能声称 GPU 延迟同时改善；该方法的直接部署收益主要是准确率、SOPs、稀疏率和 bias 存储。

## 4. 代码改造

- `models/layer.py`：加入完整/状态低秩 FTBC 模式、共享状态门控、bias 存储统计、无同步脉冲计数和临时张量优化；
- `calibration.py`：加入在线充分统计、通道级 `3x3` 岭回归和过发放加权校准；
- `models/VGG.py`：加入全模型 FTBC 模式切换；
- `spike_stats.py`：加入 FTBC 参数/字节统计和统计开关；
- `scripts/experiments/run_state_ftbc_ablation.py`：加入公平校准、完整消融和纯推理延迟测量；
- `tests/test_state_low_rank_ftbc.py`、`tests/test_spike_stats.py`：覆盖 bias、求解器、存储量和统计开关。

## 5. 推荐使用方式

- `T=1/2`：使用完整 FTBC；
- `T=4/8`：优先使用 `H_STATE_LR_SOPS`，综合收益最明显；
- `T=16/32`：若目标平台重视 SOPs 和存储，使用 `H_STATE_LR_SOPS`；若部署目标是当前 PyTorch GPU 最低延迟，需要进一步实现融合 CUDA/Triton kernel 后再下结论。
